# Браузерный E2E: Playwright поверх прод-сборки, включая конфликт

Ревью показало, что полный путь гостя в браузере не подтверждён: в спецификации
(#2) E2E были **вне объёма**, а компонентные тесты фронта замокают SDK и не
проверяют связку «браузер ↔ реальный Fastify ↔ SQLite». Решаем добавить
**Playwright** и покрыть два сценария: полный путь от выбора типа события до
подтверждения записи и конфликт на одном слоте между двумя гостями (включая
исчезновение занятого времени из числа доступных). Тем самым область #2 в части
«E2E вне объёма» снимается.

## Что именно проверяем

- **Путь гостя** (`e2e/booking.spec.ts`): `/book` → тип → дата и время (последний
  день окна, первый свободный слот) → данные → подтверждение → экран успеха;
  затем `/admin` показывает созданную встречу в ленте.
- **Конфликт**: два браузерных контекста выбирают один и тот же слот; первый
  подтверждает запись, второй получает `409 CONFLICT` и блок «Это время уже
  занято» (ADR-0015). После «Выбрать другое время» сетка перечитывается, и занятый
  слот становится `disabled` — занятое время исчезает из числа доступных.

## Как поднимается приложение

- `playwright.config.ts` поднимает **прод-сборку** одним сервером
  (`npm run start --workspace backend`): бекенд отдаёт и `/api`, и статику фронта
  (ADR-0014), поэтому отдельный dev-сервер и прокси не нужны. `baseURL` —
  `http://127.0.0.1:3100`.
- БД изолирована: `DATABASE_PATH=:memory:` (ADR-0006), поэтому прогон
  воспроизводим и не трогает данные разработчика; тесты сами занимают свободные
  слоты, а не полагаются на предзаполненное состояние.
- `npm run e2e` = `npm run build` + `playwright test`; цель `make e2e`; в CI —
  отдельный job `e2e` (`npx playwright install --with-deps chromium` + отчёт
  артефактом).

## Considered Options

- **Ручной отчёт проверки вместо автотеста** — отброшен: не даёт регрессионной
  защиты и требует ручного воспроизведения на каждый прогон.
- **Playwright поверх dev-серверов (Vite + tsx)** — отброшен: два процесса и
  прокси усложняют конфиг и не проверяют реальную упаковку; прод-сборка
  одновременно подтверждает и вариант развёртывания.
- **Cypress** — отброшен: Playwright даёт несколько браузерных контекстов в одном
  тесте (нужно для гонки за слот) и не требует отдельного рантайма.
- **Компонентные тесты как «полный сценарий»** — отброшен: они мокают SDK и не
  видят реальный сервер, БД и гонку.

## Consequences

- Область #2 в части тестов расширяется: E2E больше не вне объёма.
- CI получает отдельный job; `make check` остаётся быстрым (линтер + типы + тесты) и
  E2E не тянет.
- Тесты в каждом сценарии сами находят свободный слот, поэтому порядок прогона и
  повторные запуски не ломают их.
