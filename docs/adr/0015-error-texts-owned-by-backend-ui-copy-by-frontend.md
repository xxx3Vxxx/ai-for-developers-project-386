# Тексты ошибок принадлежат бекенду, UI-copy — фронтенду

`message` в конверте ошибки — русское сообщение, которое клиент показывает как есть
(ADR-0005). Поэтому единственный источник текстов для всего, что обнаруживает
сервер, — бекенд: `backend/src/messages.ts` с двумя словарями `errorMessages`
(`code` → строка) и `fieldMessages` (`поле` → `случай` → строка); роуты и
валидаторы берут строки только оттуда. Статичный copy интерфейса — заголовки,
подписи, кнопки, пустые состояния и состояния конфликта/недоступности (ADR-0011,
ADR-0012) — живёт на фронтенде под `frontend/src/copy/` (`landing.ts`, `book.ts`,
`admin.ts`, `common.ts`), именованными объектами по экранам, без i18n-фреймворка и
только по-русски.

**Правило видимости.** `message` показывается дословно только для
`VALIDATION_ERROR` без `fields` и как fallback для необработанных кодов. Для кодов
с экранным состоянием (`CONFLICT`, `INVALID_SLOT`, `DATE_OUT_OF_WINDOW`,
`EVENT_TYPE_NOT_FOUND`, `SERVICE_UNAVAILABLE`, `INTERNAL_ERROR`) текст берётся из
`copy/`, а `message` уходит в лог. При наличии `fields` по-полевые сообщения
показываются под полями, а верхний `message` не дублируется.

**Зеркало.** Тексты до-отправочной валидации полей обязаны существовать и на
фронте: `frontend/src/copy/fields.ts` повторяет `fieldMessages` посимвольно — это
единственное разрешённое дублирование. Расхождение ловят тесты на обеих сторонах:
каждая ассертит свои литералы, и правка одной стороны роняет CI. Канонический
список строк для ревью — в спецификации `#2`; третьего модуля с текстами не
заводим.

## Considered Options

- **Фронт владеет всем пользовательским текстом, `message` — служебный.**
  Отброшено: противоречит ADR-0005 и заставляет фронт переводить каждый `code` в
  строку, хотя для `VALIDATION_ERROR` текст уже готов на сервере.
- **Общий workspace-модуль текстов, импортируемый обеими сторонами.** Отброшено:
  ради шести строк полей — новый workspace и правка сборки с типами; выгода не
  окупает.
- **Общий JSON-файл в корне, читаемый обоими.** Отброшено: третий источник правды —
  ровно то, чего решение избегает.

## Consequences

- `frontend/src/copy/fields.ts` несёт комментарий-указатель на
  `backend/src/messages.ts`; правка порогов (100, 500, 254/64, 15) трогает оба файла
  и оба теста.
- Тесты бекенда по-прежнему бьют по `code`; точные строки фиксируют отдельные
  ассерты, а не форма контракта ответа.
- Тексты, зависящие от конфигурации (длина рабочего окна в сообщении о
  длительности, зона сервиса в сноске), подставляются из `GET /api/config`, а не
  хардкодятся.
- Полная карта строк — разделы «UI/UX» и «Ошибки» спецификации `#2`.
