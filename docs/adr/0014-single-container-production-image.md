# Прод-образ: один контейнер, статика с бекенда, `PORT` из env

Приложение собирается **одним образом из корневого `Dockerfile`**: Fastify-бекенд
отдаёт собранный фронтенд (`frontend/dist`) через `@fastify/static` и слушает один
порт `PORT` из env. Отдельного сервиса для статики нет. Так требует автопроверка
Хекслета: `hexlet-check` собирает только наш корневой `Dockerfile`
(`docker build -f code/Dockerfile code`) и ждёт `GET /` → 200 от одного
поднявшегося приложения; её `docker-compose.yml` — из приватного образа проекта, а
не наш. Один origin на всё заодно снимает CORS: в проде `/api` и SPA живут рядом,
в dev прокси `/api` на бекенд остаётся за Vite (ADR-0008 не затронут, конфиг
фронта не меняется).

- **Образ многостадийный**: `deps` (`npm ci`, все workspace'ы с dev-зависимостями)
  → `contracts` (генерация типов контрактов, см. ADR-0008) → `build` (`tsc`
  бекенда + `vite build` фронта) → `prod-deps` (`npm ci --omit=dev`) → `runtime`.
  База — `node:22-bookworm-slim` (паритет с CI; обновление мажора — отдельное
  решение). Стадии, где может компилироваться `better-sqlite3`, получают
  `python3 make g++`. Рантайм работает под встроенным пользователем `node`, не
  root.
- **`PORT` читается только из env**, дефолт — `loadConfig()` (ADR-0013), то есть
  `3000`. `ENV PORT` в образе не хардкодим (свой `PORT` подставит окружение
  проверки), `EXPOSE 3000` — информационный. `HOST` — `0.0.0.0` из той же
  конфигурации.
- **SQLite внутри контейнера** — по `DATABASE_PATH` (ADR-0013):
  `WORKDIR /app` + дефолт `./data/calendar.sqlite` → `/app/data/calendar.sqlite`.
  Каталог создаётся в образе и принадлежит `node`, чтобы non-root писал. `VOLUME`
  в `Dockerfile` не объявляем (тома — забота compose/`docker run`, `VOLUME` лишь
  плодит анонимные); документируем `-v calendar-data:/app/data`. Данные **не
  стираются** при старте: схема идемпотентна, сид — `INSERT OR IGNORE`
  (ADR-0006), поэтому рестарт и пересоздание контейнера безопасны, а без тома
  поднимается свежая БД.
- **Статика — `@fastify/static`** с корнем, вычисляемым константой в коде
  относительно расположения собранного `backend/dist` (env для этого не заводим —
  набор ADR-0013 не расширяется). `setNotFoundHandler`: `GET` вне `/api` с
  `Accept: text/html` → `index.html` (200), иначе — конверт `404 NOT_FOUND`
  (ADR-0009). `index.html` отдаётся `no-cache`, хешированные ассеты `/assets/*` —
  `immutable`. `/health` и `/api/*` статикой не перехватываются.
- **`HEALTHCHECK` не объявляем**: рантайм и его проверки размечает compose
  проверки, а образ не должен тянуть в slim-базу `wget`/`curl` ради таймингов,
  которые нам ничего не дают.
- **Локальная сборка и разработка**: корневой `.dockerignore` (`node_modules`,
  `dist`, `.git`, `coverage`, `data`, `*.log`) держит контекст маленьким, `make
  docker-build` собирает образ, `make docker-run` поднимает его с томом под БД.
  Повседневная разработка — как раньше, `npm run dev` (Vite-прокси), Docker
  участвует только в прод-сборке и автопроверке. Цель `setup` не заводим: её в
  своём Makefile гоняет образ Хекслета, а не наш.

## Considered Options

- **Отдельный сервис для фронта (nginx/`serve`) в своём `docker-compose.yml`** —
  отброшен: автопроверка видит один поднявшийся app из нашего `Dockerfile`, второй
  контейнер ей недоступен; к тому же два origin'а возвращают вопрос CORS, который
  в одной связке просто не существует.
- **`ENV PORT=8080`** как в референсе Хекслета — отброшен: референсный дефолт
  ничего не гарантирует (проходящие студенты слушают разные порты), а расхождение
  с нашим `PORT=3000`/README путает.
- **`VOLUME /app/data` в `Dockerfile`** — отброшен: тома должен размечать тот, кто
  запускает контейнер; объявленный `VOLUME` создаёт анонимный том и удивляет
  compose.
- **Коммитить `generated/` или собирать фронт без `tsc`** (обход коллизии с
  ADR-0008) — отброшены: первый даёт дрейф и шум в диффах, второй теряет проверку
  типов в единственном шаге, который видит автопроверка.

## Consequences

- Прод-сборка возможна одной командой `docker build .` из корня без
  предварительного шага — это и есть контракт автопроверки.
- ADR-0008 уточнён: генерация контрактов выполняется стадией `contracts` внутри
  прод-`Dockerfile` и по-прежнему не коммитится.
- ADR-0013 остаётся единственным набором переменных: `PORT`, `HOST`,
  `DATABASE_PATH` и остальные читаются один раз в `loadConfig()`; `Dockerfile`
  новых переменных не вводит.
- `.env.example` (требуется ADR-0013, сейчас отсутствует) добавляется вместе с
  упаковкой.
- Реализация `Dockerfile`, `.dockerignore` и целей `Makefile` — отдельная работа,
  не часть этого решения.
