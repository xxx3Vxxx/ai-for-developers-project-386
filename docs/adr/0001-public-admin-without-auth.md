# Админская часть `/admin` публична, без авторизации

У сервиса две роли — владелец календаря и гость, — но регистрации и входа нет:
владелец это заранее заданный профиль. Мы решили не защищать `/admin`: страница
создания типов событий и список предстоящих встреч доступны любому, кто знает
адрес. Альтернатива (сессия или токен для владельца) отброшена как выходящая за
объём учебного проекта.

## Consequences

Раз страница открыта, email гостей из списка предстоящих встреч виден всем.
При выходе в реальную эксплуатацию первым шагом нужно добавить аутентификацию
владельца.
